**CLOUTE** — Telegram-бот с веб-приложением (Mini App) внутри Telegram.
Агрегатор студенческих мероприятий Москвы. Бот: **@clout_msk_bot**.

- Язык: русский. Стек: Python (Flask + python-telegram-bot 21.5), PostgreSQL 18, HTML/CSS/JS (`index.html`).

## 2. ГЛАВНОЕ: гибридная архитектура

Три независимые части, потому что с росс. сервера Telegram API заблокирован (ТСПУ).
Данные хранятся в РФ (152-ФЗ), а связь с Telegram — за рубежом.

```
[ Пользователь в Telegram ]
            |
[ ПОЧТАЛЬОН (connector.py) ]   <- за рубежом (Railway). Общается с Telegram.
            |  ходит к Складу по HTTPS с заголовком X-Internal-Key
[ СКЛАД (росс. сервер, Timeweb, Москва) ]  <- ВСЕ персональные данные тут
   ├─ bot.py        (API/Flask, режим «только Склад», Telegram OFF)
   ├─ database.py   (PostgreSQL)
   ├─ PostgreSQL 18 (данные в РФ)
   └─ index.html    (WebApp, nginx, https://cloute.ru)
```

## 4. ДЕПЛОЙ — АВТОМАТИЧЕСКИЙ (ручной scp больше НЕ нужен!)

**Рабочий цикл:**
1. Открыть Claude Code в нужной папке.
2. Дать задачу словами.
3. Claude Code правит, проверяет компиляцию, коммитит и пушит в GitHub.
4. Изменение САМО доезжает до прода.
5. Проверить в боте/приложении.

**Как доезжает:**
- Почтальон (cloute-bot): пуш → Railway деплоит сам.
- WebApp (cloute-webapp): пуш → cron на сервере раз/мин запускает /root/deploy-webapp.sh
  → тянет код, копирует index.html в /var/www/cloute/.
- Склад (cloute-server): пуш → cron раз/мин /root/deploy-server.sh → тянет код,
  ПРОВЕРЯЕТ компиляцию (py_compile), копирует bot.py/database.py в /opt/cloute/,
  systemctl restart cloute. Если код битый — обновление отменяется, бот жив на старом.

**Доступ сервера к GitHub:** Deploy Keys (read-only) + SSH-псевдонимы:
- github-webapp → /root/.ssh/cloute_deploy → cloute-webapp
- github-server → /root/.ssh/cloute_server_deploy → cloute-server

**Скрипты/логи/клоны на сервере:**
- /root/deploy-webapp.sh (лог /root/deploy-webapp.log), клон /root/cloute-webapp
- /root/deploy-server.sh (лог /root/deploy-server.log), клон /root/cloute-server
- cron: crontab -l (две строки, раз в минуту)

## 5. Инфраструктура

### Росс. сервер (Склад + WebApp)
- Timeweb, Москва, Ubuntu 24.04. IP 72.56.247.235. Домен cloute.ru (HTTPS Let's Encrypt).
- Склад: /opt/cloute (bot.py, database.py, .env, venv). WebApp: /var/www/cloute/index.html.
- nginx: /api/ → 127.0.0.1:8080, остальное → WebApp.
- systemd сервис cloute (Restart=always, под root). PostgreSQL 18, порт 5432, БД cloute, юзер cloute.
- Telegram-часть ВЫКЛЮЧЕНА (RUN_TELEGRAM ≠ "1") → режим «только API/Склад».
- **Картинки (афиши/аватарки): на РОССИЙСКОМ сервере** `/var/www/cloute/uploads/` → отдаются как `https://cloute.ru/uploads/...` (imgbb убран, данные из РФ не уходят).
  - ⚠️ Ручные настройки на сервере, которых НЕТ в git (при пересоздании сервера повторить):
    - папка `/var/www/cloute/uploads` (сервис под root создаёт сам, но лучше чтоб была);
    - в `/etc/nginx/sites-available/cloute` добавлено `client_max_body_size 20M;` (дефолт 1MB резал фото; бэкап `cloute.bak`).
  - ⚠️ В БЭКАП рядом с базой ОБЯЗАТЕЛЬНО включить `/var/www/cloute/uploads` — иначе картинки потеряются при восстановлении.

### Railway (Почтальон)
- Проект vigilant-appreciation, сервис cloute-bot. Procfile: web: python connector.py.
- Python зафиксирован .python-version = 3.12. Старый Postgres не используется.

### Технические детали фронта:
- Лента: автообновление каждые 30 сек, фильтры Все/Сегодня/На неделе, hot=1 идут первыми («🔥 Хит»), прошедшие скрыты (filterPast).
- Все алерты через `alert()`, НЕ `showAlert`.
- Афиши/аватарки грузятся на РФ-сервер через `/api/upload` (base64 → `/var/www/cloute/uploads`, отдаёт nginx). imgbb НЕ используется.
- Внешние ссылки (канал/билет/маршрут): `openExt()` + `normUrl()` — нормализуют (t.me/@ник/без https) и открывают «родными» методами Telegram. НЕ использовать сырой `window.open` для ссылок оргов.
- Управляющие списки (openAE/openOE/статистика) работают на `allEvs`; детальная статистика события — экран `#sst` (`openEvStats`).
